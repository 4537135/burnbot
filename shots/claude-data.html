Burnbot 1.2 · source walkthrough

What Burnbot reads from Claude

Every piece of information Burnbot takes from Claude Code, where it comes from, and what it turns into. It has three sources. Almost everything comes from the session logs; the hooks add a few things the logs can't tell you in time; the claude command is only used for AI summaries, and only if you turn them on.

Three sources

Session logs
~/.claude/projects/**/*.jsonl

One JSON object per line, appended as you work. Burnbot reads each file from where it last stopped, so a live session shows up within a couple of seconds. Subagent logs (<session>/subagents/agent-<id>.jsonl) are read too.

Fields read →
Hook events
~/.claude/settings.json → hook.sh → inbox/

Three hooks: PermissionRequest, Stop, SessionEnd. The script copies what Claude Code sends into a folder and prints nothing. The app reads each file once, then deletes it.

Fields read →
The claude command
claude -p --no-session-persistence

Off by default. When on, Burnbot runs your own claude once per finished session to write a two-line summary. Burnbot reads only the answer, and it must match a JSON schema.

What's sent →
Not from Claude Which app is in front (its bundle id) and how many seconds since you last touched the keyboard or mouse. Both come from macOS without a permission prompt and decide whether you're "away".

What it keeps about each session

Alongside the minute rows, each log carries a little about the session it belongs to. Some is saved; some lives only while the app runs.

Saved in store.json

  • Log path, how far it's been read, when it last changed
  • Session id, project, branch
  • Title, and whether you named it yourself
  • Files edited: paths only, up to 500
  • Time of your last prompt
  • Response ids already counted, so nothing is counted twice (forgotten after two quiet weeks)
  • Open questions still waiting for your answer
  • The day this log last counted a commit

Only in memory, live

  • Bash runs waiting for their result: the command and its kind
  • Red-run ledger: failures on the way to a green
  • Live signals for the robot: a line, a prompt (up to 500 typed characters), a question, an answer, an edit, a run starting, a run's result with its last 2 KB of output

Saved in sessions.json

  • The last 50 session recaps: title, project, branch, start and end, minutes, files edited, wins, commits, pull request, runs still red
  • The AI summary if one was made: what got done, what's next

Fields read from hook events

The hooks tell Burnbot right away when Claude is blocked on you or has stopped. The script runs in the background and prints nothing, so Claude Code behaves as before. While the app is closed the inbox folder doesn't exist, so nothing is written.

What leaves your Mac, and only if you ask

AI summaries are the only time anything Burnbot read goes anywhere. They use your own claude with no tools, no settings, no saved session, a small model, a spending cap, 60 seconds at most, and 20 a day at most.

Sent

  • Title, project, branch and minutes hands-on
  • Your prompts from that stretch: the last 12, typed text only, 200 characters each, read fresh from the log
  • Paths of edited files, up to 15
  • Results: the wins, how many commits, whether a pull request was opened

Never sent

  • File contents
  • Claude's replies or thinking
  • Command output
  • Anything pasted

In the logs, not read yet

Fields Claude Code writes that Burnbot currently ignores, from the same 35 logs. Some could be useful later; a few are skipped on purpose. Claude's own text and thinking are never read.

Inside message.usage

  • cache_creation.ephemeral_5m_input_tokens / ephemeral_1h_input_tokens: cache writes split by how long they live
  • server_tool_use.web_search_requests / web_fetch_requests
  • service_tier, speed, inference_geo, iterations

On assistant lines

  • stop_reason: why the response ended
  • effort, thinkingDurationMs, toolInputStreamMs
  • apiError, isApiErrorMessage: failed calls
  • requestedModel, next to the model actually used
  • attributionSkill, attributionPlugin, attributionMcpServer, attributionMcpTool: what a call came from
  • entrypoint, version: CLI, IDE or desktop, and Claude Code's version

On user lines

  • permissionMode: default, plan, auto…
  • promptSource, imagePasteIds: where a prompt came from, pasted images
  • toolUseResult.structuredPatch: the exact lines added and removed by each edit
  • toolUseResult.durationMs on some tools

Whole line types

  • cost-state: Claude Code's own session totals (lines added and removed, API and tool time, usage by model)
  • mode: switches into plan or auto mode
  • agent-name, tools-used
  • system: compaction, retries, hook errors
  • queue-operation: messages you queued while Claude was busy
  • session-owner: account and organisation ids, skipped on purpose
